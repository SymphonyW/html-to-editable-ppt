# Framework notes

The converter auto-detects several common slide layouts, but explicit selectors are more reliable when the HTML is generated by a framework.

| Framework / pattern | Suggested selector |
|---|---|
| Reveal.js | automatic detection; otherwise `.reveal .slides > section` |
| Marp exported HTML | `section` or the specific slide section class in the export |
| Slidev static export | inspect the export and use the repeated slide-page class |
| Generic deck | `.slide` |
| Custom deck | `.ppt-page`, `.page`, or `[data-slide]` |

Example:

```bash
node scripts/convert.mjs deck.html deck.pptx --selector '.ppt-page'
```

If slides are nested, prefer a selector that matches the actual leaf slide nodes rather than both parent and child containers.

## Decks with JS fit-to-window scaling

Custom HTML decks often wrap slides in a stage that a script scales with `transform: scale(...)` to fit the browser window (look for a `resize` handler setting `style.transform`). Conversion is unaffected because coordinates are mapped relative to each slide's own rect — but hide viewer chrome (nav bars, sidebars) before screenshotting for visual comparison, and pass the selector matching the slide element itself, not the stage wrapper.
